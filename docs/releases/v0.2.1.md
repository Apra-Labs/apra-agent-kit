## What's fixed

### Scheduler no longer crashes the host

The scheduler validation threw when a scheduled workflow lacked routing config,
which brought down the entire host on startup (exit code 1). Non-routable
schedules are now logged as warnings and filtered out. Hard errors (unknown
workflow, bad cron, invalid timezone) still throw.

### Hello workflow is routable and schedulable

The template's `hello` tool now has `routing` config, so the scheduler can
dispatch it and the router can classify it as a workflow. The scheduler's
`hello-every-2m` schedule works out of the box.

### `npm install` works on Windows

`execFileSync('npm', ...)` failed silently on Windows because `npm` is a `.cmd`
wrapper. The create script now uses `shell: true` on Windows so `npm.cmd`
resolves correctly. Previously, every Windows user saw `! npm install failed`
and had to run it manually.

### Docker entrypoint CRLF fix

Shell scripts generated on Windows had CRLF line endings, causing
`exec: no such file or directory` in Linux containers. Both the VM and Azure
Functions Dockerfiles now strip `\r` from entrypoint scripts at build time.

### `@apralabs/apra-fleet` resolves in Docker

The published `@apralabs/apra-fleet` package has a `file:` internal dependency
that npm hoists incorrectly — sub-packages land in `node_modules/@apralabs/`
but the parent package itself is dropped. Two fixes:

1. **`ensureApralabs()` no longer nukes npm-installed packages.** It was
   replacing the entire `@apralabs` directory with a symlink, which doesn't
   survive Docker's overlay filesystem. Now it fills in missing packages
   individually without deleting what's already there.

2. **Docker entrypoints copy the global install at startup.** Both VM and Azure
   Functions entrypoints copy `@apralabs/apra-fleet` from the working global
   install into local `node_modules` before the host starts.

### Chat UI shows the greeting, not JSON

The hello workflow now returns an `answer` field that the router's
`unwrapWorkflowResult` extracts for the chat UI. Previously, the chat showed
raw `{"who":"world","host":"Sid","greeting":"..."}`.

## What's improved

### Create UX

The `npm create` output now shows:

- **Kit version** in the opening line: `Creating my-agent… (agent-kit v0.2.1)`
- **Enabled modules** with one-line descriptions after generation
- **Scheduler details** — schedule name, workflow, and cron expression
- **Better error messages** — npm install failures show the exit code

### Hello workflow CLI output

`npm run hello` prints a human-readable greeting instead of raw JSON:

```
  Hello, world! It's lovely to meet you.
  (host: Sid, who: world)
```

### Hostname output trimmed

`command('hostname')` in the hello workflow body is now trimmed — no trailing
`\n` in the result.

### Scheduler logs schedule details on startup

The scheduler now logs each schedule with its name, target workflow, cron
expression, timezone, and next run time:

```
[scheduler]   hello-every-2m → hello (*/2 * * * * UTC, next: 2026-10-01T08:34:00.000Z)
[scheduler] started 1 schedule(s)
```

### UUID deprecation warning suppressed

The template's `package.json` now includes `"overrides": { "uuid": "^11.0.0" }`
to silence the `uuid@9` deprecation warning from a transitive dependency.
