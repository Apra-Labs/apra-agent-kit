## Install

```bash
npm create @apralabs/agent-kit my-agent
cd my-agent
npm run doctor   # verify environment
npm run hello    # run the starter workflow
```

The generator copies the kit framework, writes a starter `hello` workflow, and
offers to install [Apra Fleet](https://github.com/Apra-Labs/apra-fleet) and the
Claude CLI. It explains each step before it asks.

## What ships in the package

Everything listed in `package.json` `files` is published to npm. The table below
maps every published directory to what it does.

### Core framework

| Directory | Files | What it does |
|-----------|-------|--------------|
| **`pool/`** | `index.mjs`, `worker-pool.mjs`, `worker-dispatcher.mjs`, `worker-lock.mjs`, `roster.mjs`, `member-manager.mjs`, `ephemeral-factory.mjs`, `pooled-fleet-api.mjs`, `fleet-text.mjs`, `config.mjs`, `cleanup.mjs` | Worker pool lifecycle — roster-based member management, mutex locking, ephemeral worker scaling, tiered dispatch (pool → ephemeral → queue), and graceful cleanup |
| **`transport/`** | `stdio-fleet.mjs`, `ensure-apralabs.mjs` | stdio-based Fleet transport layer; locates the Fleet binary and verifies the `@apralabs` install |

| **`host/strategies/`** | `open-ended.mjs`, `plan-execute.mjs` | Two run-loop strategies: open-ended (single-pass agent) and plan-execute (planner → executor multi-step) |
| **`host/jobs/`** | `index.mjs`, `interface.mjs`, `config.mjs`, `record.mjs`, `in-process.mjs`, `durable.mjs` | Async job dispatch with two backends — in-process (SQLite) for local dev and Azure Durable Functions for production; job records, status tracking, concurrency limits |
| **`host/chat/`** | `routes.mjs`, `app.mjs`, `transcript.mjs` | Web chat UI — HTML served from Express, transcript persistence across messages, themed styling |
| **`host/memory/`** | `index.mjs`, `conversation-context.mjs`, `run-state.mjs`, `long-term.mjs`, `learner.mjs`, `preloader.mjs`, `events.mjs`, `routes.mjs` | Three-tier memory system — conversation context (within-session turns), run state (crash recovery), and long-term memory with FSRS-6 spaced-repetition decay. Exposes `remember`, `recall`, `forget`, and `promote` agent tools |
| **`mcp/`** | `main.mjs`, `server.mjs`, `http.mjs`, `auth.mjs`, `registry.mjs`, `registry-helpers.mjs`, `fleet-text.mjs` | Model Context Protocol server — tool registry, HTTP transport, Bearer token auth, Fleet text formatting |

| **`comm/azure-functions/`** | `main.mjs`, `index.mjs`, `http.mjs`, `orchestrator.mjs`, `activity.mjs` | Azure Functions adapter — HTTP triggers, Durable Functions orchestrator and activity bindings |

## CI/CD

| Workflow | Trigger | What it does |
|----------|---------|--------------|
| `ci.yml` | Push/PR to `main` | Unit tests, create-command tests, integration tests (Docker), load tests |
| `ci-host.yml` | Push/PR to `main` | Host module tests (config, registry, executor, router, strategies, jobs, chat) |
| `ci-e2e.yml` | Push/PR to `main` | End-to-end Docker Compose tests (VM and Durable profiles) |
| `publish.yml` | GitHub release published | Runs tests, then `npm publish --access public --provenance` |

Packages are published with [npm provenance](https://docs.npmjs.com/generating-provenance-statements)
linking every published version to the exact GitHub Actions run that built it.
